# Security Review (Pre-Pentest Self-Assessment)

Internal review done ahead of the officers' penetration test, mapped to the OWASP Top 10 (2021). Goal: fix what we control in the app; document what's delegated to Keycloak/infra so reviewers don't re-flag it.

## CSRF / cookies / sessions (what the officers usually probe)

- Auth token cookie `kc_token` is `httpOnly`, `sameSite: 'strict'`, and `secure` when `NODE_ENV=production` (`backend/middleware/keycloakAuth.js` `setTokenCookie`). `httpOnly` + `sameSite=strict` already blocks the classic CSRF pattern (cookie can't be read by JS, and won't be sent cross-site).
- **Verify before the officers test**: confirm `NODE_ENV=production` (or equivalent) is actually set in whatever environment they'll hit, otherwise `secure` stays `false` and the cookie can travel over plain HTTP.
- Most state-changing calls go through the `Authorization: Bearer` header (not cookies), which is inherently CSRF-immune since browsers don't auto-attach custom headers cross-site.
- No explicit CSRF token (double-submit) exists. Not added in this pass since the primary auth path (Bearer header) isn't cookie-driven; only add this if reviewers specifically flag cookie-only mutating endpoints.

## Other findings reviewed, low risk / no action taken

- One `prisma.$executeRawUnsafe` call in `backend/scripts/seed-attendance-demo-data.js` — hardcoded table names array, not user input, dev-only seed script. No SQL injection path.
- CORS origin list in `backend/server.js` is a fixed allowlist (no wildcard `*`), fine as-is.

## Known accepted gaps (documented so reviewers don't need to re-report)

- **Rate limit is generous (600/15min)** on general API routes - tuned for normal app usage. Sensitive endpoints (password set, user enable/disable) now have a tighter 20/15min limit. If a login/token-proxy endpoint is added, apply a similar tighter limit.
- **Input validation on user and quiz routes only** — `validateInput.js` middleware is applied to `POST /users`, `PUT /users/:id`, `POST /quizzes`, and `PUT /quizzes/:id`. Other POST/PUT routes (~109) do not have explicit input validation yet. Extend as needed, prioritizing file/announcement creation routes.
- Full route-by-route authorization audit (`requirePermission.js`, `adminScopeMiddleware.js`) was out of scope for this pass — only the token-verification layer was audited/fixed.
- **Swagger UI disabled by default in production** — `/api-docs` is off unless `ENABLE_SWAGGER=true` is set explicitly in production. In development it's on by default. The route has a relaxed CSP (inline scripts/styles allowed) necessary for swagger-ui-express.
- **8 high-severity transitive dependency vulnerabilities remain** — in `next` (docs subproject), `form-data` (via axios/jsdom), `undici` (via winston-elasticsearch), `tmp` (via exceljs), `fast-xml-builder` (via minio). These require upstream patches; no direct app code is affected.

## Automated scan

- **Local**: `pnpm security:scan` (`scripts/security/zap-baseline.sh`) runs an OWASP ZAP baseline scan (Docker) against your locally running backend. Run this before the officers' session and triage any new findings here.
- **CI (manual)**: `.github/workflows/zap-baseline.yml` runs the same scan via `workflow_dispatch` against any reachable URL you provide (a staging deployment or tunnel). It does not spin up Keycloak/Postgres/MinIO in CI - that's heavier than useful for a baseline scan; use the local script for that.
